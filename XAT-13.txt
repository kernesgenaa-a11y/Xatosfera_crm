<description>
## Контекст

Відповіді API cast-ятся через `as unknown[]`, `as Record<string, unknown>` — немає type safety на рівні runtime. Zod (v3.25.76) вже встановлений.

## Файли

* **Створити:** `src/types/schemas.ts` (Zod-схеми)
* **Створити:** `src/types/api.ts` (TypeScript типи, згенеровані з Zod)
* **Змінити:** `src/integrations/cloudflare/client.ts` (додати валідацію)

## Кроки

1. Створити `src/types/schemas.ts` з Zod-схемами для всіх entities:

   ```ts
   import { z } from 'zod';
   
   export const PropertySchema = z.object({
     id: z.string(),
     title: z.string(),
     address: z.string().nullable(),
     price: z.number().nullable(),
     status: z.enum(['active', 'sold', 'reserved', 'archived']),
     // ... всі поля з PROPERTY_FULL_COLUMNS у worker-index.js
   });
   
   export const ClientSchema = z.object({ ... });
   export const DealSchema = z.object({ ... });
   // ... UserSchema, NoteSchema, CalendarEventSchema, etc.
   ```
2. Створити `src/types/api.ts`:

   ```ts
   export type Property = z.infer<typeof PropertySchema>;
   export type Client = z.infer<typeof ClientSchema>;
   ```
3. Додати валідацію в API клієнт або custom hooks:

   ```ts
   const data = await cloudflareApi.get('/api/properties');
   return PropertySchema.array().parse(data);
   ```
4. Визначити поля по константах з `worker-index.js`:
   * `PROPERTY_FULL_COLUMNS` (рядок \~93)
   * `NOTE_COLUMNS` (рядок \~94)
   * `REPORT_COLUMNS` (рядок \~95)
   * `USER_PUBLIC_COLUMNS` (рядок \~92)

## Acceptance Criteria

- [ ] Zod-схеми для мінімум 6 entities (Property, Client, Deal, User, Note, CalendarEvent)
- [ ] TypeScript типи згенеровані з `z.infer<>`
- [ ] `npm run build` проходить
- [ ] API відповіді валідуються через `.parse()` або `.safeParse()`
- [ ] Помилки валідації логуються в console (не крашать UI)

<title>Увімкнути strict TypeScript (поетапно)</title>
<description>
## Контекст

TypeScript strict mode повністю вимкнений. Поточні налаштування:

* `strict: false`
* `noImplicitAny: false`
* `strictNullChecks: false`
* `noUnusedLocals: false`
* `noUnusedParameters: false`

## Файли

* **Змінити:** `tsconfig.json`, `tsconfig.app.json`
* **Виправити помилки у:** всіх файлах `src/` (\~95 файлів)

## Кроки (поетапно, кожен крок = окремий коміт)

### Крок 1: Увімкнути `noUnusedLocals` та `noUnusedParameters`

1. У `tsconfig.json` встановити `"noUnusedLocals": true`, `"noUnusedParameters": true`
2. У `tsconfig.app.json` встановити те саме
3. `npx tsc --noEmit` — виправити всі помилки (видалити або prefix `_` невикористовувані змінні)

### Крок 2: Увімкнути `strictNullChecks`

1. Встановити `"strictNullChecks": true`
2. `npx tsc --noEmit` — виправити null-check помилки (додати `?.`, `?? defaultValue`, `!` де впевнені)
3. Особлива увага: `AuthContext.tsx` (user може бути null), `cloudflare/client.ts` (cache може бути null)

### Крок 3: Увімкнути `noImplicitAny`

1. Встановити `"noImplicitAny": true`
2. `npx tsc --noEmit` — додати типи до всіх `any` параметрів
3. Замінити `as any` на правильні типи де можливо

### Крок 4: Увімкнути `strict: true`

1. Замінити окремі flags на `"strict": true`
2. `npx tsc --noEmit` — виправити решту

## НЕ робити

* Не використовувати `@ts-ignore` або `@ts-expect-error` крім крайніх випадків
* Не замінювати `any` на `unknown` без подальшого narrowing
* Не змінювати бізнес-логіку — тільки типізацію

## Acceptance Criteria

- [ ] `tsconfig.json` має `strict: true` (або еквівалент)
- [ ] `npx tsc --noEmit` проходить без помилок
- [ ] `npm run build` проходить
- [ ] Кількість `as any` у коді зменшена мінімум на 50%
- [ ] Кожен крок — окремий коміт для легкого review
</description>
</sub-issue>

<title>Налаштувати pre-commit hooks (husky + lint-staged)</title>
<description>
## Контекст

Pre-commit hooks відсутні. Код може бути закомічений без lint перевірок.

## Файли

* **Створити:** `.husky/pre-commit`
* **Змінити:** `package.json` (додати `lint-staged`, `husky`, `prettier` та scripts)

## Кроки

1. Встановити залежності:

   ```bash
   npm install -D husky lint-staged prettier
   ```
2. Ініціалізувати husky:

   ```bash
   npx husky init
   ```
3. Створити `.husky/pre-commit`:

   ```bash
   npx lint-staged
   ```
4. Додати конфігурацію `lint-staged` в `package.json`:

   ```json
   "lint-staged": {
     "*.{ts,tsx}": ["eslint --fix", "prettier --write"],
     "*.{json,md,css}": ["prettier --write"]
   }
   ```
5. Створити `.prettierrc`:

   ```json
   {
     "singleQuote": true,
     "trailingComma": "all",
     "printWidth": 100,
     "semi": true
   }
   ```
6. Додати script в `package.json`: `"prepare": "husky"`
7. Тест: зробити зміну у `.ts` файлі → `git commit` → переконатися що lint-staged запускається

## НЕ робити

* Не форматувати весь проєкт одним комітом (буде величезний diff)
* Не блокувати коміти через TypeScript помилки (поки strict не увімкнений)

## Acceptance Criteria

- [ ] `npm install` автоматично налаштовує husky hooks (`prepare` script)
- [ ] `git commit` запускає lint-staged
- [ ] ESLint помилки блокують коміт
- [ ] Prettier форматує змінені файли
- [ ] `.prettierrc` існує з конфігурацією
</description>

* **Видалити кеш з:** `src/integrations/cloudflare/client.ts` (рядки \~22-40: `cache`, `cacheGet`, `cacheSet`, `invalidateCache`, `clearCache`)
* **Створити hooks у:** `src/hooks/` (нова директорія)
* **Змінити:** кожна сторінка в `src/pages/` (замінити `useEffect` + `useState` на `useQuery`)

## Кроки

1. Створити `src/hooks/useProperties.ts`:

   ```ts
   import { useQuery, useMutation, useQueryClient } from '@tanstack/react-query';
   import { cloudflareApi } from '@/integrations/cloudflare/client';
   
   export function useProperties(params?) {
     return useQuery({
       queryKey: ['properties', params],
       queryFn: () => cloudflareApi.get('/api/properties', params),
       staleTime: 5 * 60 * 1000,
     });
   }
   ```
2. Аналогічно створити: `useClients.ts`, `useDeals.ts`, `useCalendar.ts`, `useNotes.ts`, `useUsers.ts`, `useReports.ts`, `useMatches.ts`, `useNotifications.ts`

   ```ts
   // БУЛО:
   const [data, setData] = useState([]);
   const [loading, setLoading] = useState(true);
   useEffect(() => { fetchData(); }, []);
   
   // СТАЛО:
   const { data, isLoading } = useProperties();
   ```
4. Для мутацій (create/update/delete) використовувати `useMutation` + `queryClient.invalidateQueries()`
5. Видалити кастомний кеш з `client.ts` (`cache`, `cacheGet`, `cacheSet`, `invalidateCache`, `clearCache`)
6. Зберегти `apiFetch()` як низькорівневий fetch wrapper (без кешу)

## НЕ робити

* Не змінювати API ендпоінти

## Acceptance Criteria
