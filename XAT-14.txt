<title>Серверна пагінація (cursor-based) для списків</title>
<description>
## Контекст

Всі ендпоінти повертають ВСІ записи без ліміту. При 1000+ об'єктах — повільний response і перевантажений UI.

## Файли

### Бекенд (worker)

* **Змінити:** `worker/src/properties.ts` (або `worker-index.js`)
* **Змінити:** `worker/src/clients.ts`
* **Змінити:** `worker/src/deals.ts`
* **Змінити:** `worker/src/notes.ts`

### Фронтенд

* **Змінити:** `src/hooks/useProperties.ts` (або сторінки якщо hooks ще не створені)
* **Змінити:** `src/pages/PropertiesPage.tsx`
* **Змінити:** `src/pages/ClientsPage.tsx`
* **Змінити:** `src/pages/DealsPage.tsx`
* **Змінити:** `src/pages/NotesPage.tsx`

## Кроки

### Бекенд

1. Додати query параметри `?limit=20&cursor=<last_id>` до GET ендпоінтів
2. SQL запит:

   ```sql
   SELECT * FROM properties
   WHERE id > ?cursor
   ORDER BY id ASC
   LIMIT ?limit + 1
   ```
3. Якщо повернулось `limit + 1` записів → `hasMore: true`, повернути `limit` записів + `nextCursor: last_id`
4. Response формат:

   ```json
   {
     "data": [...],
     "nextCursor": "abc123",
     "hasMore": true
   }
   ```
5. Зворотна сумісність: якщо `limit` не передано — повертати все (як зараз)

### Фронтенд

6. Використовувати `useInfiniteQuery` з React Query:

   ```ts
   const { data, fetchNextPage, hasNextPage } = useInfiniteQuery({
     queryKey: ['properties', filters],
     queryFn: ({ pageParam }) => cloudflareApi.get('/api/properties', { limit: 20, cursor: pageParam }),
     getNextPageParam: (lastPage) => lastPage.hasMore ? lastPage.nextCursor : undefined,
   });
   ```
7. Додати кнопку "Завантажити ще" або infinite scroll

## Acceptance Criteria

- [ ] `GET /api/properties?limit=20` повертає максимум 20 записів + `nextCursor`
- [ ] `GET /api/properties?limit=20&cursor=abc` повертає наступну сторінку
- [ ] `GET /api/properties` без limit — зворотна сумісність (всі записи)
- [ ] Фронтенд показує "Завантажити ще" коли `hasMore: true`
- [ ] Працює для properties, clients, deals, notes
