<description>
## Контекст

Поточна система має `role` поле в `users` таблиці, але перевірок ролей немає ні на бекенді, ні на фронтенді. Всі авторизовані юзери мають однакові права.

## Файли

### Бекенд

* **Створити:** `worker/src/middleware/rbac.ts`
* **Змінити:** `worker/src/index.ts` (або `worker-index.js`) — додати middleware
* **Змінити:** `worker/src/users.ts` — ендпоінт зміни ролі

### Фронтенд

* **Створити:** `src/hooks/usePermissions.ts`
* **Змінити:** `src/contexts/AuthContext.tsx` — додати role в контекст
* **Змінити:** компоненти, де потрібно ховати кнопки по ролі

## Кроки

### Ролі

1. Визначити ролі:
   * `admin` — повний доступ + управління юзерами
   * `manager` — CRUD properties, clients, deals, notes
   * `viewer` — тільки читання

### Бекенд

2. Створити `worker/src/middleware/rbac.ts`:

   ```ts
   const PERMISSIONS = {
     admin: ['*'],
     manager: ['properties:*', 'clients:*', 'deals:*', 'notes:*', 'calendar:*', 'files:*'],
     viewer: ['properties:read', 'clients:read', 'deals:read', 'notes:read'],
   };
   
   export function requirePermission(permission: string) {
     return (request: Request, user: User) => {
       const userPerms = PERMISSIONS[user.role] || [];
       if (!userPerms.includes('*') && !userPerms.includes(permission)) {
         return new Response('Forbidden', { status: 403 });
       }
     };
   }
   ```
3. Додати перевірку перед кожним mutation handler:

   ```ts
   // POST /api/properties
   const forbidden = requirePermission('properties:create')(request, user);
   if (forbidden) return forbidden;
   ```
4. `DELETE /api/users/:id` — тільки admin
5. `PUT /api/users/:id/role` — тільки admin

### Фронтенд

6. Створити `usePermissions.ts`:

   ```ts
   export function usePermissions() {
     const { user } = useAuth();
     return {
       canCreate: user?.role === 'admin' || user?.role === 'manager',
       canDelete: user?.role === 'admin',
       canManageUsers: user?.role === 'admin',
       isViewer: user?.role === 'viewer',
     };
   }
   ```
7. Ховати кнопки "Створити", "Видалити" для viewer
8. Ховати сторінку Users для не-admin

## Acceptance Criteria

- [ ] 3 ролі визначені: admin, manager, viewer
- [ ] Бекенд повертає 403 для неавторизованих дій
- [ ] Viewer не може створювати/змінювати/видаляти
- [ ] Тільки admin може управляти юзерами
- [ ] Фронтенд ховає кнопки відповідно до ролі
- [ ] `npx wrangler deploy` проходить

## Контекст

## Кроки

1. Замінити точний match на scoring алгоритм:

   ```ts
   function calculateMatchScore(property: Property, client: ClientRequirements): number {
     let score = 0;
     const maxScore = 100;
     
     // Ціна (30 балів): в діапазоні budget ±10%
     if (property.price >= client.budgetMin * 0.9 && property.price <= client.budgetMax * 1.1) {
       score += 30;
     } else if (property.price >= client.budgetMin * 0.8 && property.price <= client.budgetMax * 1.2) {
       score += 15; // частковий збіг
     }
     
     // Район (25 балів): точний збіг
     if (property.district === client.preferredDistrict) score += 25;
     
     // Тип (20 балів)
     if (property.type === client.preferredType) score += 20;
     
     // Кімнати (15 балів)
     if (property.rooms >= client.minRooms && property.rooms <= client.maxRooms) score += 15;
     
     // Площа (10 балів)
     if (property.area >= client.minArea) score += 10;
     
     return score;
   }
   ```
2. Ендпоінт `GET /api/matches?clientId=xxx` повертає properties з score:

   ```json
       { "property": {...}, "score": 85, "matchDetails": {"price": true, "district": true, ...} },
       { "property": {...}, "score": 60, "matchDetails": {...} }
     ]
   }
   ```
3. Сортувати по score DESC, показувати тільки score > 30
